# Revenue Management Support — 수익 관리 의사결정 지원 요구사항

> **영역**: 운영적 의사결정 지원 (도메인 섹션 6 기반)
> **우선순위**: 중간 (P2)
> **배경**: PMS, OTA, 경쟁사 데이터가 각기 다른 시스템에 산재하여 요율 결정이 직감과 경험에 의존함. AI 예측 도입 시 RevPAR 최대 35% 개선이 가능하나, 50%의 호텔이 의사결정에 필요한 데이터에 접근하지 못하고 있음.

---

## 1. 기능 요구사항

### 1-1. 데이터 통합 및 신호 수집

| ID | 요구사항 | 우선순위 |
|----|---------|---------|
| RM-F01 | 시스템은 내부 PMS 데이터(예약, 점유율, ADR)를 일간 단위로 자동 수집해야 한다 | P0 |
| RM-F02 | OTA(주요 채널) 경쟁사 요율 데이터를 일간 단위로 수집하여 비교 뷰를 제공해야 한다 | P1 |
| RM-F03 | 로컬 이벤트(콘서트, 스포츠, 전시, 컨퍼런스) 캘린더를 연동하여 수요 급등 예상일을 식별해야 한다 | P1 |
| RM-F04 | 과거 동일 기간(YoY, WoW) 성과 데이터를 자동으로 비교 조회할 수 있어야 한다 | P1 |
| RM-F05 | 예약 픽업 속도(Pickup Pace)를 과거 기간 대비 실시간으로 시각화해야 한다 | P1 |

### 1-2. 수요 예측

| ID | 요구사항 | 우선순위 |
|----|---------|---------|
| RM-F10 | AI는 과거 데이터와 외부 신호(이벤트, 날씨, 연휴)를 결합하여 향후 30/60/90일 점유율 예측값을 제공해야 한다 | P1 |
| RM-F11 | 예측값은 구간(신뢰 범위)과 함께 제공되어야 하며, 단일 숫자가 아닌 낙관/기준/보수 시나리오를 포함해야 한다 | P2 |
| RM-F12 | 실적 대비 예측값의 오차율(MAPE)을 월별로 추적하여 모델 정확도를 관리자가 확인할 수 있어야 한다 | P2 |

### 1-3. 요율 설정 권고 (Rate Recommendation)

| ID | 요구사항 | 우선순위 |
|----|---------|---------|
| RM-F20 | AI는 수요 예측, 경쟁사 요율, 잔여 재고를 종합하여 날짜별 권고 요율을 제안해야 한다 | P1 |
| RM-F21 | 권고 요율에는 제안 근거(예: "경쟁사 A 매진, 픽업 3배 증가, 이벤트 D-3")가 함께 표시되어야 한다 | P1 |
| RM-F22 | 담당자는 AI 권고를 수락/수정/거절할 수 있으며, 거절 시 사유를 입력해야 한다 | P1 |
| RM-F23 | 최소 투숙일수(LOS) 제한 설정에 대한 AI 권고를 제공해야 한다 | P2 |
| RM-F24 | 채널별(OTA/직접예약/GDS) 재고 배분 비율에 대한 권고를 제공해야 한다 | P2 |

### 1-4. 단체 예약 수락 의사결정 지원

| ID | 요구사항 | 우선순위 |
|----|---------|---------|
| RM-F30 | 단체 예약 요청 입력 시(객실 수, 기간, 제시 가격) 수락/거절 시나리오별 기대 수익을 시뮬레이션해야 한다 | P2 |
| RM-F31 | 시뮬레이션 결과에는 기회비용(해당 기간 개별 예약 잠재 수익)이 명시되어야 한다 | P2 |

### 1-5. 성과 대시보드

| ID | 요구사항 | 우선순위 |
|----|---------|---------|
| RM-F40 | 일간/주간/월간 RevPAR, ADR, 점유율을 한눈에 확인하는 대시보드를 제공해야 한다 | P1 |
| RM-F41 | 채널별 예약 구성비와 OTA 수수료 비용을 시각화해야 한다 | P1 |
| RM-F42 | AI 권고 수락률과 권고 기반 의사결정의 실적 기여를 추적하는 피드백 루프 지표를 제공해야 한다 | P2 |

## 3. 핵심 의사결정 시나리오

도메인 섹션 6의 의사결정 흐름을 시스템이 지원해야 하는 시나리오:

### 시나리오 A — 객실 요율 실시간 결정
```
트리거: 예약 픽업 속도 이상 급증 감지
  → AI 분석: 경쟁사 요율 변동, 이벤트 정보, 잔여 재고 확인
  → 권고: 요율 +N% 인상, LOS X박 이상 제한 제안
  → 담당자: 수락 또는 수동 조정 후 적용
```

### 시나리오 B — 저수요 기간 프로모션 결정
```
트리거: 30일 후 점유율 예측이 목표치 하회 경고
  → AI 분석: 픽업 페이스, 경쟁사 할인 현황, 마케팅 ROI 데이터
  → 권고: 특정 채널에 N% 할인 프로모션 또는 패키지 구성 제안
  → 담당자: 승인 후 채널 적용
```

### 시나리오 C — 단체 예약 수락 여부 결정
```
입력: 단체 80객실, 3/15~17, 12만원/박 제시
  → AI 계산:
      수락 시 확정 수익: 1.44억
      거절 시 기대 수익: (예상 점유율 70%) × ADR 13만원 = 1.04억
  → 권고: 수락 권고, 단 취소 패널티 강화 및 F&B 마진 재협상 조건
```

## 4. 수집 신호 유형 (도메인 섹션 7 기반)

### 외부 신호
- 로컬 이벤트 캘린더 (콘서트, 스포츠, 컨퍼런스)
- 공휴일·연휴 캘린더
- 날씨 예보 API
- 항공편 운항 데이터

### 시장/경쟁 신호
- 경쟁사 요율 (OTA 스크래핑 또는 파트너 데이터)
- STR/HotStats 시장 평균 점유율
- OTA 가격 비교 가용성

### 내부 신호
- 실시간 예약 픽업 (PMS 연동)
- 잔여 재고 (객실 유형별)
- 취소/변경 패턴
- 채널별 전환율 및 수수료

## 5. 사용자 시나리오

```
As a Revenue Manager,
I want to 오늘 아침 출근하면 어젯밤 픽업 현황과 AI 권고 요율을 대시보드에서 확인하고 싶다,
So that 수작업으로 경쟁사 요율을 조사하고 스프레드시트를 정리하는 시간을 줄일 수 있다.

As a 총지배인,
I want to 단체 예약 요청이 들어왔을 때 수락/거절 시 기대 수익 비교를 즉시 볼 수 있길 원한다,
So that 경험에만 의존하지 않고 데이터 기반으로 협상 조건을 결정할 수 있다.

As a Revenue Manager,
I want to AI가 권고한 요율 변경이 실제로 수익에 어떤 영향을 미쳤는지 사후에 추적하고 싶다,
So that AI 권고의 신뢰도를 검증하고 점점 더 잘 활용할 수 있다.
```
