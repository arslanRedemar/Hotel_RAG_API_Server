# RAG Assistant — AI 기반 내부 지식 검색 요구사항

> **영역**: AX 솔루션 핵심 기회 영역 1
> **우선순위**: 최우선 (P0)
> **배경**: 호텔 내 SOP, 매뉴얼, 정책 문서가 PDF·이메일·종이에 산재하여 직원이 필요한 정보를 찾는 데 수십 분이 소요됨. 73%의 조직이 "파편화된 지식 소스"를 가장 큰 문제로 꼽음.

---

## 1. 기능 요구사항

### 1-1. 문서 수집 및 인덱싱 (Document Ingestion)

| ID | 요구사항 | 우선순위 |
|----|---------|---------|
| RAG-F01 | 시스템은 PDF, TXT, Word(.docx) 형식의 문서를 업로드하여 벡터 DB에 인덱싱할 수 있어야 한다 | P0 |
| RAG-F02 | 문서 업로드 시 파일명, 업로드 일시, 부서, 버전 정보를 메타데이터로 함께 저장해야 한다 | P0 |
| RAG-F03 | 기존에 인덱싱된 문서를 새 버전으로 교체할 수 있어야 하며, 이전 버전은 이력으로 보존되어야 한다 | P1 |
| RAG-F04 | 인덱싱 완료 후 처리된 청크(chunk) 수와 소요 시간을 관리자에게 반환해야 한다 | P1 |
| RAG-F05 | 디렉토리 단위 일괄 인덱싱을 지원해야 한다 | P1 |

### 1-2. 자연어 질의응답 (Chat Interface)

| ID | 요구사항 | 우선순위 |
|----|---------|---------|
| RAG-F10 | 직원은 한국어 자연어로 질문하면 관련 문서를 기반으로 한 답변을 받아야 한다 | P0 |
| RAG-F11 | 답변에는 출처 문서명과 해당 섹션 정보가 함께 제공되어야 한다 | P0 |
| RAG-F12 | 시스템은 세션 내 대화 이력을 유지하여 후속 질문(follow-up)에 맥락 있는 답변을 제공해야 한다 | P0 |
| RAG-F13 | 관련 문서가 없을 경우 "해당 정보를 찾을 수 없습니다"라고 명확히 안내해야 하며, 임의로 내용을 생성(hallucination)해서는 안 된다 | P0 |
| RAG-F14 | 단일 질문에 대해 복수의 문서에서 정보를 종합하여 답변할 수 있어야 한다 | P1 |

### 1-3. 부서별 접근 권한 (Access Control)

| ID | 요구사항 | 우선순위 |
|----|---------|---------|
| RAG-F20 | 문서에 부서(프런트, 하우스키핑, F&B, 시설, 인사, 수익관리)별 접근 권한을 설정할 수 있어야 한다 | P1 |
| RAG-F21 | 직원 계정은 소속 부서에 허용된 문서만 검색 결과로 노출되어야 한다 | P1 |
| RAG-F22 | 관리자(Admin)는 모든 부서 문서에 접근할 수 있어야 한다 | P1 |

### 1-4. 문서 버전 관리 (Version Management)

| ID | 요구사항 | 우선순위 |
|----|---------|---------|
| RAG-F30 | 동일 문서의 신규 버전 등록 시 직원에게 변경 알림을 발송해야 한다 | P1 |
| RAG-F31 | 문서 목록에서 현재 유효 버전과 이전 버전을 구분하여 표시해야 한다 | P2 |

## 3. 데이터 요구사항

- **지원 문서 형식**: PDF, TXT, DOCX
- **청크 크기**: 500자 (기본값), 50자 겹침(overlap)
- **검색 결과 수**: 상위 5개 청크(기본값, 설정 가능)
- **임베딩 모델**: OpenAI `text-embedding-3-small` (또는 동급 이상)
- **LLM 모델**: GPT-4o-mini 이상 (한국어 지원 필수)
- **벡터 DB**: ChromaDB (로컬 퍼시스턴트 모드)

## 4. API 명세

### POST /api/v1/ingest
문서를 벡터 DB에 인덱싱한다.

**Request**
```json
{
  "collection_name": "hotel_docs"
}
```

**Response**
```json
{
  "message": "문서 인제스트 완료",
  "doc_count": 150
}
```

### POST /api/v1/chat
자연어 질문에 RAG 기반 답변을 반환한다.

**Request**
```json
{
  "message": "체크인 SOP 절차를 알려줘",
  "session_id": "user-123"
}
```

**Response**
```json
{
  "answer": "체크인 절차는 다음과 같습니다...",
  "sources": ["docs/checkin_sop.pdf"],
  "session_id": "user-123"
}
```

### GET /api/v1/history/{session_id}
세션의 대화 이력을 조회한다.

### DELETE /api/v1/history/{session_id}
세션 및 대화 이력을 삭제한다.

## 5. 사용자 시나리오 (User Stories)

```
As a 신입 하우스키핑 직원,
I want to 청소 체크리스트를 자연어로 질문하면 즉시 답변을 받고 싶다,
So that 선임 직원에게 매번 물어보지 않고도 업무를 수행할 수 있다.

As a 프런트 오피스 직원,
I want to VIP 응대 프로토콜을 키워드로 검색하여 출처와 함께 확인하고 싶다,
So that 구버전 문서를 사용하는 실수를 방지할 수 있다.

As a 관리자,
I want to 새 SOP 문서를 업로드하면 관련 직원에게 자동 알림이 가길 원한다,
So that 모든 직원이 최신 절차를 인지하고 있음을 보장할 수 있다.
```

## 6. 제약 사항

- OpenAI API 키는 서버 환경 변수로만 관리하며 클라이언트에 노출 금지
- 외부 인터넷 연결이 없는 환경을 위해 로컬 LLM 대체 구성을 고려해야 한다 (P2)
- 개인정보(투숙객 데이터)가 포함된 문서는 인덱싱 전 마스킹 처리가 선행되어야 한다
