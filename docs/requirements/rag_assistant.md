> **우선순위**: 최우선 (P0)
> **작성일**: 2026-03-29
> **버전**: 2.0

## 1. 배경 및 맥락 (Context)

### 1-1. 현재 상황

200실 규모 호텔에서 직원이 업무 중 정보를 찾아야 하는 상황은 하루에도 수십 번 발생한다. 체크인 중 VIP 프로토콜이 갑자기 기억나지 않을 때, 하우스키핑이 특정 투숙객 알레르기 대응 절차를 확인해야 할 때, 야간 당직자가 비상 상황에서 담당자 연락처를 찾아야 할 때 등이 대표적이다.

그러나 현재 이 정보들은 다음과 같이 파편화되어 있다:

| 정보 유형 | 현재 저장 위치 | 문제점 |
|---------|-------------|-------|
| SOP 매뉴얼 | 부서별 공유 드라이브 (PDF) | 최신 버전 불분명, 검색 불가 |
| 긴급 연락처 | 각자 휴대폰 메모, 인쇄물 | 퇴직자 정보 미삭제, 분실 위험 |
| 고객 응대 가이드 | 이메일 첨부파일 | 버전 통제 없음, 탐색 어려움 |
| 브랜드 규정 | 제본된 종이 매뉴얼 | 개정 시 전량 폐기·재배포 필요 |
| 법정 규정 요약 | 부서장 개인 파일 | 인수인계 시 소실 위험 |

### 1-2. 이해관계자 및 고통 포인트

**신입 직원 (채용 후 3개월 이내)**
- 매일 평균 12~18회 선임에게 질문함 (내부 비공식 조사 기준)
- "선임이 바빠 보여서 못 물어보고 그냥 넘어간 경우"가 응답자의 67%
- 온보딩 기간 중 정보 부재로 인한 서비스 실수가 퇴직 사유 2위

**프런트 오피스 직원**
- VIP 체크인 전 관련 프로토콜을 찾는 데 평균 8분 소요
- 여러 버전의 SOP 중 최신 본을 확신하지 못한 채 업무를 진행하는 경우 빈번
- 컴플레인 응대 중 관련 정책을 실시간으로 조회할 수 없어 즉답 불가 상황 발생

**하우스키핑 슈퍼바이저**
- 객실 유형(스위트/일반/장기투숙)별 청소 기준이 다르나 구두 전달에 의존
- 신규 투입 아르바이트 직원의 실수 교정에 슈퍼바이저 시간의 30% 이상 소요

**관리자 (부서장·총지배인)**
- SOP 개정 시 전 직원에게 전달 여부를 확인할 방법이 없음
- 외부 감사 시 "어떤 절차를 기준으로 직원이 업무를 하는지" 증명 불가

### 1-3. 근본 원인 분석

```
표면 문제: "직원이 정보를 못 찾는다"
           ↓
중간 원인: 문서가 여러 곳에 분산되어 있고, 검색이 불가능하며,
           최신 버전인지 확인하기 어렵다
           ↓
근본 원인: 문서 생성·배포·관리 체계가 없고, 직원이 정보를
           "어디서 어떻게 찾아야 하는지"에 대한 단일 진입점이 없다
```

### 1-4. 비즈니스 임팩트

- 정보 탐색 시간: 직원 1인당 하루 평균 47분 (업무 시간의 약 10%)
- 서비스 오류 비용: 잘못된 정보 적용으로 인한 고객 컴플레인 처리 비용 월 평균 추정
- 트레이닝 비용: 정보 접근성 부재로 인한 반복 교육 비용이 신규 채용 비용의 40%
- 직원 만족도: 정보 접근 불편이 직원 퇴직 설문에서 3위 내 언급

## 2. 문제 정의 (Problem Statement)

> **"어떻게 하면 호텔 직원이 근무 중 어떤 상황에서도 필요한 운영 정보를 30초 이내에 정확하게 찾을 수 있도록, 분산된 지식을 하나의 대화형 AI로 통합할 수 있을까?"**

### 해결해야 할 핵심 질문들

1. 직원이 질문 방식을 바꾸거나 키워드를 정확히 알지 못해도 원하는 정보를 찾을 수 있는가?
2. 답변의 근거(출처 문서)를 직원이 즉시 확인할 수 있는가?
3. 오래된 문서가 아닌 현재 유효한 최신 정보만 답변에 사용되는가?
4. 부서별로 접근이 제한된 민감 정보가 통제되는가?

---

## 3. 성공 비전 (Vision of Success)

RAG Assistant 도입 후 6개월 시점의 기대 모습:

- 신입 직원이 선임에게 반복적으로 질문하는 횟수가 70% 감소
- 프런트 직원이 VIP 체크인 전 프로토콜 확인에 소요하는 시간이 8분 → 30초로 단축
- 관리자가 SOP 업데이트 시 직원 전달 여부를 시스템에서 확인 가능
- 외부 감사 시 "직원이 어떤 기준으로 업무했는지" AI 조회 이력으로 증명 가능

## 4. 기능 요구사항

### 4-1. 문서 수집 및 인덱싱 (Document Ingestion)

|----|---------|---------|---------|

| RAG-F02 | 문서 업로드 시 파일명·업로드 일시·부서·버전을 메타데이터로 저장해야 한다 | 메타데이터 누락 없이 저장되고 검색 필터로 사용 가능 | P0 |
| RAG-F03 | 동일 문서의 신규 버전 등록 시 이전 버전을 검색 대상에서 자동 제외하되 이력은 보존해야 한다 | 구버전 문서가 답변 소스로 사용되지 않음을 테스트로 확인 | P1 |
| RAG-F04 | 인덱싱 완료 후 처리된 청크 수, 소요 시간, 실패 청크 목록을 응답에 포함해야 한다 | API 응답에 `chunk_count`, `elapsed_ms`, `failed_chunks` 필드 존재 | P1 |
| RAG-F05 | 디렉토리 단위 일괄 인덱싱을 지원하되, 개별 파일 실패 시 전체를 중단하지 않아야 한다 | 10개 파일 중 1개 오류 시 나머지 9개는 정상 인덱싱 완료 | P1 |
| RAG-F06 | 50MB 초과 파일은 청크 분할 전 크기 초과 오류를 반환하고, 오류 메시지에 허용 크기를 명시해야 한다 | 51MB 파일 업로드 시 `413 Payload Too Large` + 안내 메시지 | P1 |

### 4-2. 자연어 질의응답 (Chat Interface)

|----|---------|---------|---------|

| RAG-F14 | 복수의 문서에서 정보를 종합하여 답변할 수 있어야 한다 | 2개 이상의 소스를 종합한 답변 생성 테스트 케이스 통과 | P1 |
| RAG-F15 | 답변 생성 중 오류 발생 시 사용자에게 오류 메시지와 함께 재시도 방법을 안내해야 한다 | OpenAI 타임아웃 시뮬레이션 시 `503` + 안내 메시지 반환 | P1 |

## 6. API 명세

### POST /api/v1/ingest
문서를 벡터 DB에 인덱싱한다.

**Request** (multipart/form-data)
```
file: <파일 바이너리>
department: "front_office" | "housekeeping" | "fb" | "facility" | "hr" | "revenue"
version: "2.1"  (선택, 기본값: "1.0")
```

**Response 200**
```json
{
  "document_id": "doc-uuid-001",
  "file_name": "checkin_sop_v2.1.pdf",
  "chunk_count": 48,
  "elapsed_ms": 2340,
  "failed_chunks": [],
  "version": "2.1",
  "department": "front_office",
  "indexed_at": "2026-03-29T09:00:00Z"
}
```

**Response 413**
```json
{
  "error": "FILE_TOO_LARGE",
  "message": "파일 크기가 허용 한도(50MB)를 초과합니다. 현재 파일: 51.2MB",
  "max_size_mb": 50
}
```

### POST /api/v1/chat
자연어 질문에 RAG 기반 답변을 반환한다.

**Request**
```json
{
  "message": "VIP 체크인 절차에서 어메니티 배치 기준을 알려줘",
  "session_id": "session-uuid-456"
}
```

**Response 200**
```json
{
  "answer": "VIP 체크인 시 어메니티 배치 기준은 다음과 같습니다...",
  "sources": [
    {
      "document_id": "doc-uuid-001",
      "file_name": "vip_protocol_v3.pdf",
      "section": "3.2 어메니티 배치 기준",
      "relevance_score": 0.91
    }
  ],
  "session_id": "session-uuid-456",
  "tokens_used": 312
}
```

**Response 200 (정보 없음)**
```json
{
  "answer": "죄송합니다. 해당 내용에 대한 정보를 등록된 문서에서 찾을 수 없습니다. 관련 SOP가 아직 업로드되지 않았을 수 있습니다. 담당자에게 문의하거나 관리자에게 문서 등록을 요청해 주세요.",
  "sources": [],
  "session_id": "session-uuid-456",
  "tokens_used": 58
}
```

### GET /api/v1/history/{session_id}
세션의 대화 이력을 조회한다.

**Response 200**
```json
{
  "session_id": "session-uuid-456",
  "messages": [
    { "role": "user", "content": "VIP 체크인 절차는?", "created_at": "2026-03-29T09:01:00Z" },
    { "role": "assistant", "content": "VIP 체크인 시...", "created_at": "2026-03-29T09:01:02Z" }
  ],
  "message_count": 2
}
```

### DELETE /api/v1/history/{session_id}
세션 및 대화 이력을 삭제한다.

## 7. 사용자 시나리오 (User Stories)

### 시나리오 A — 신입 직원의 실시간 업무 조회
```
상황: 신입 하우스키핑 직원이 스위트룸 청소 중 규격에 맞는 어메니티 배치 기준을 몰라
      선임에게 연락했으나 바빠서 답을 못 받음

As a 신입 하우스키핑 직원,
I want to "스위트룸 어메니티 배치 기준" 이라고 타이핑하면 즉시 절차를 알려주는 AI가 있길 원한다,
So that 선임이 바쁠 때도 독립적으로 정확한 기준에 맞춰 업무를 완료할 수 있다.

수락 기준:
- 질문 입력 후 3초 이내 답변 출력
- 답변에 출처 문서명과 항목이 포함됨
- 답변 내용이 최신 SOP 기준과 일치함
```

### 시나리오 B — 컴플레인 대응 중 즉각 조회
```
상황: 프런트 직원이 고객 컴플레인 응대 중 환불 정책을 즉시 확인해야 하는 상황

As a 프런트 오피스 직원,
I want to 고객 앞에서 자연스럽게 "당일 취소 환불 정책이 어떻게 되나요?" 라고 물으면
          정확한 정책을 바로 받을 수 있길 원한다,
So that 고객에게 "확인 후 연락드리겠습니다"라는 말 없이 현장에서 즉답할 수 있다.

수락 기준:
- 정책 관련 문서가 인덱싱된 경우 정확한 내용 반환
- 출처 문서(예: "고객 서비스 정책 v2.3") 표시
- 이전 대화 "오늘 오후 3시 취소인데요" 맥락을 유지한 후속 답변 가능
```

### 시나리오 C — 관리자의 문서 배포 확인
```
상황: 운영 매니저가 새 컴플레인 응대 SOP를 업데이트하고 전 직원 인지 여부를 확인해야 함

As a 운영 매니저,
I want to 새 SOP를 업로드하면 해당 부서 직원에게 자동으로 알림이 가고
          확인 여부를 추적할 수 있길 원한다,
So that "전달했는데 몰랐다"는 상황을 방지하고 감사 시 전달 증거를 제시할 수 있다.

수락 기준:
- 업로드 즉시 해당 부서 직원 전원에게 알림 발송
- 알림 발송 이력(수신자, 시간, 채널)이 관리자 조회 가능
- 이전 버전 문서는 검색 결과에서 자동 제외됨
```
