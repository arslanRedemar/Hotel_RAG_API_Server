# Admin Panel — Hotel AX 운영 관리 대시보드 요구사항

> **영역**: AX 솔루션 운영 인프라
> **우선순위**: P1 (Revenue Management 병행)
> **작성일**: 2026-03-29
> **버전**: 1.0

---

## 1. 배경 및 맥락 (Context)

### 1-1. 현재 상황

Hotel RAG API Server는 FastAPI + LangChain + ChromaDB 스택으로 구축된 백엔드 서버로, RAG Assistant · SOP 디지털화 · 워크오더 자동화 · 컴플라이언스 감사 · 수익 관리 5개 모듈을 운영한다. 현재 서버 운영 상태는 다음과 같이 파악하기 어렵다:

| 항목 | 현재 상황 | 문제점 |
|------|-----------|--------|
| API 성능 지표 | 서버 로그 직접 확인 (SSH) | 비개발자 접근 불가, 실시간 파악 불가 |
| LLM 호출 추적 | LangSmith 웹 콘솔 별도 접속 | 컨텍스트 전환 필요, 팀 공유 어려움 |
| 인덱싱된 문서 현황 | DB 직접 조회 | SQL 지식 필요, 비기술 담당자 사용 불가 |
| 토큰 비용 | LangSmith 개별 조회 | 월별 비용 추이 파악 불가 |
| 사용자 관리 | DB 직접 CRUD | 휴먼 에러 위험, 이력 미기록 |
| 부하 테스트 결과 | CI/CD 로그 확인 | 이력 비교 불가, 비직관적 |

### 1-2. 이해관계자 및 고통 포인트

**호텔 IT 매니저 (주 사용자)**
- 서버 장애 감지를 위해 매일 SSH로 로그를 직접 확인해야 함
- LLM 토큰 비용이 얼마나 발생하는지 실시간으로 모를 때 경영진에 보고 불가
- 인덱싱된 문서가 최신 상태인지, 오래된 문서가 혼재하는지 파악하지 못함
- 비활성 사용자 계정이 존재해도 즉시 비활성화할 방법이 없음

**개발자 / DevOps (보조 사용자)**
- LangSmith 트레이스와 API 로그를 번갈아 보며 디버깅해야 함
- 부하 테스트가 CI/CD에서 자동 실행되지만 결과를 비교·분석하는 UI가 없음
- RAG 품질 저하 여부를 LangSmith 데이터셋 평가 결과와 연계해 확인하기 어려움

**운영 매니저**
- 어떤 질문이 답변 실패(hallucination 방지로 거절)했는지 파악 불가
- 워크오더 자동 분류 정확도가 떨어졌을 때 원인 파악에 시간이 많이 걸림
- 수익 관리 AI 권고 이력을 날짜별로 검토하고 싶으나 조회 UI가 없음

### 1-3. 근본 원인 분석

```
표면 문제: "서버 상태를 모른다"
           ↓
중간 원인: 운영 지표(성능·비용·품질)가 여러 시스템(SSH·LangSmith·DB·CI 로그)에
           분산되어 있고, 비기술 사용자가 접근할 수 있는 통합 UI가 없다
           ↓
근본 원인: API 서버 개발 시 운영 가시성(operational visibility)을 위한
           관리 인터페이스가 설계에 포함되지 않았음
```

### 1-4. 비즈니스 임팩트

- 장애 감지 시간: 현재 평균 15~30분 (로그 직접 확인 기준) → 목표 2분 (헬스 대시보드)
- 비용 파악 지연: 월말에야 LangSmith 청구서로 토큰 비용 확인 → 주간 추이 모니터링 목표
- 문서 관리 오류: SQL 직접 조작 중 실수로 인덱스 데이터 손상 사례 발생
- IT 매니저 업무 시간: 운영 지표 수집·보고에 주 평균 4시간 소요 → 1시간 이내 목표

## 2. 문제 정의 (Problem Statement)

> **"어떻게 하면 호텔 IT 매니저와 개발자가 Hotel RAG API Server의 성능·비용·품질·콘텐츠를 브라우저 하나에서 실시간으로 파악하고 관리할 수 있을까?"**

### 해결해야 할 핵심 질문들

1. 비개발자(IT 매니저)가 SSH 없이도 서버 상태와 LLM 비용을 즉시 파악할 수 있는가?
2. LangSmith 트레이스·평가·데이터셋을 별도 탭 없이 관리 패널 안에서 확인할 수 있는가?
3. 인덱싱된 문서 목록을 UI에서 검색·수정·삭제·재인덱싱할 수 있는가?
4. 부하 테스트 결과를 CI/CD 실행 이력 단위로 비교·분석할 수 있는가?
5. 기존 Hotel API JWT를 재사용하여 별도 인증 인프라 없이 접근 제어가 가능한가?

---

## 3. 성공 비전 (Vision of Success)

Admin Panel 출시 후 3개월 시점의 기대 모습:

- IT 매니저가 매일 아침 대시보드 한 화면으로 서버 상태·전일 토큰 비용·미응답 질문 수를 5분 안에 파악
- 인덱싱 문서 오류 발생 시 SSH 없이 UI에서 즉시 재인덱싱
- LangSmith 트레이스 이상(응답 지연·오류율 급증) 감지 시 개발자가 패널에서 원인 추적
- 부하 테스트 결과가 CI 실행마다 자동 기록되어 성능 회귀를 그래프로 비교 가능
- 신규 직원 계정 생성·권한 변경을 IT 매니저가 직접 UI로 처리 (DB 접근 불필요)

## 7. 사용자 시나리오 (User Stories)

### 시나리오 A — IT 매니저의 아침 점검 루틴 (Phase 1)
```
상황: IT 매니저가 출근 후 전날 밤 API 서버 이상 여부와 LLM 비용을 확인해야 함

As a 호텔 IT 매니저,
I want to 브라우저에서 관리 패널을 열면 서버 상태·토큰 비용·오류율을 한눈에 볼 수 있길 원한다,
So that SSH 없이 5분 안에 일일 점검을 마치고 이상 시 즉시 대응할 수 있다.

수락 기준:
- 대시보드 진입 즉시 API/DB/Redis 상태가 색상 인디케이터로 표시됨
- 당일 및 전일 토큰 사용량과 추정 비용이 카드로 표시됨
- 오류율이 기준치 초과 시 경고 배지 표시
```

### 시나리오 B — 개발자의 RAG 오류 트레이스 디버깅 (Phase 1)
```
상황: 개발자가 특정 시간대에 RAG 응답 오류가 급증했다는 알람을 받음

As a 백엔드 개발자,
I want to LangSmith 트레이스를 관리 패널에서 시간 범위와 오류 상태로 필터링하여 문제가 된
          트레이스를 찾고 입출력 내용을 상세 확인하길 원한다,
So that 별도 LangSmith 콘솔 접속 없이 빠르게 원인을 파악하고 수정할 수 있다.

수락 기준:
- 날짜 범위 + 상태(오류) 필터 적용 후 오류 트레이스 목록 표시
- 트레이스 클릭 시 run 계층 트리와 오류 메시지 상세 조회
- 토큰 수와 응답 시간이 상세 패널에 표시됨
```

### 시나리오 C — IT 매니저의 문서 재인덱싱 처리 (Phase 1)
```
상황: SOP 문서가 업데이트되었으나 이전 버전이 혼재하여 일부 질문에서 구버전 정보가 반환됨

As a 호텔 IT 매니저,
I want to 문서 관리 페이지에서 구버전 문서를 아카이브 처리하고 신버전을 업로드하여
          재인덱싱할 수 있길 원한다,
So that DB 직접 접근 없이도 RAG 검색 대상 문서를 최신 상태로 유지할 수 있다.

수락 기준:
- 문서 목록에서 아카이브 처리 → RAG 검색에서 즉시 제외 확인
- 신규 문서 업로드 + 부서/버전 입력 → 인덱싱 완료 후 목록 자동 갱신
- 인덱싱 오류 발생 시 오류 메시지 UI에 표시
```

### 시나리오 D — 신규 직원 계정 생성 (Phase 1)
```
상황: 프런트 오피스 신입 직원이 RAG Assistant 접근을 위한 계정이 필요함

As a 호텔 IT 매니저,
I want to 사용자 관리 페이지에서 직원 정보를 입력하고 역할·부서를 할당하여 계정을
          즉시 생성할 수 있길 원한다,
So that IT 지식 없이도 DB 없이 계정을 관리하고 변경 이력을 감사 로그로 확인할 수 있다.

수락 기준:
- 폼 입력 후 저장 즉시 계정 활성화 (로그인 가능)
- 생성 이력이 감사 로그에 관리자 정보와 함께 기록됨
- 비활성화 처리 즉시 해당 계정 토큰 갱신 불가
```

### 시나리오 E — 개발자의 부하 테스트 결과 비교 (Phase 2)
```
상황: 개발자가 새 캐싱 레이어 도입 후 성능 개선 여부를 이전 CI 실행 결과와 비교하고 싶음

As a 백엔드 개발자,
I want to 부하 테스트 이력 페이지에서 최근 10회 실행 결과를 p95 응답 시간 차트로
          비교하여 성능 변화를 시각적으로 확인하길 원한다,
So that 엑셀 정리 없이 성능 회귀 여부를 즉시 판단하고 PR 리뷰에 근거로 활용할 수 있다.

수락 기준:
- CI 실행마다 결과가 자동 저장됨
- p95·오류율 추이 차트에서 각 실행 결과 비교 가능
- SLA 기준선(p95 < 3초) 초과 시 해당 데이터 포인트 강조 표시
```

## 8. 제약 사항

| 제약 | 내용 | 이유 |
|------|------|------|
| 별도 저장소 | Admin Panel은 Next.js 프론트엔드 전용 리포지토리로 분리 | 백엔드/프론트엔드 배포 사이클 독립, 역할 분리 |
| JWT 재사용 | Hotel RAG API Server가 발급한 JWT를 그대로 사용, 별도 인증 서버 없음 | 인증 인프라 중복 방지, 단일 계정 체계 유지 |
| Docker Compose 통합 | Admin Panel 컨테이너를 기존 `docker-compose.yml`에 서비스로 추가 | 운영 환경 단일화, 배포 복잡도 최소화 |
| 도메인 불필요 | 초기에는 로컬 및 내부 네트워크에서만 운영 (도메인·TLS 미적용) | 테스트 단계, 추후 운영 전환 시 Nginx 리버스 프록시 추가 예정 |
| LangSmith API Key | 클라이언트 번들에 노출 금지, Next.js Server Component에서만 사용 | API Key 유출 방지 (브라우저 네트워크 탭 노출 차단) |
| 폴링 주기 | 헬스 체크 30초 폴링, 실시간 WebSocket 미사용 | 구현 복잡도 대비 효과, 30초 갱신으로 충분 |
| 데이터 소유권 | Admin Panel은 데이터를 직접 소유하지 않고 Hotel API + LangSmith API를 통해서만 데이터 조회·변경 | 단일 진실 공급원(single source of truth) 유지 |
