# Work Order Automation — 업무 지시서 자동화 요구사항

> **영역**: AX 솔루션 핵심 기회 영역 3
> **우선순위**: 높음 (P1)
> **배경**: 고장 신고 → 담당자 배정 → 완료 확인의 흐름이 전화·구두로 이뤄져 처리 이력이 남지 않음. 우선순위 판단 기준 불명확으로 VIP 객실 결함이 방치되거나 안전사고 리스크가 발생함. 시설·하우스키핑 양 부서 모두 즉시 효과를 볼 수 있는 영역.

---

## 1. 기능 요구사항

### 1-1. 고장/결함 신고 접수

| ID | 요구사항 | 우선순위 |
|----|---------|---------|
| WO-F01 | 직원은 웹 또는 모바일로 객실 번호, 결함 유형, 설명을 입력하여 Work Order를 생성할 수 있어야 한다 | P0 |
| WO-F02 | 신고 시 사진 첨부를 지원해야 한다 | P1 |
| WO-F03 | 신고 접수 즉시 접수 번호와 예상 처리 시간이 신고자에게 통보되어야 한다 | P1 |
| WO-F04 | 고객(Guest)이 객실 내 QR 코드 등을 통해 직접 결함을 신고할 수 있는 채널을 지원해야 한다 | P2 |

### 1-2. AI 기반 자동 분류 및 우선순위 판단

| ID | 요구사항 | 우선순위 |
|----|---------|---------|
| WO-F10 | AI는 신고 내용을 분석하여 고장 유형(전기, 배관, 에어컨, 가구, 청결 등)을 자동 분류해야 한다 | P0 |
| WO-F11 | AI는 아래 기준으로 긴급도(Critical/High/Medium/Low)를 자동 판단해야 한다 | P0 |
|        | - Critical: 안전사고 위험, 투숙 불가 상태 | |
|        | - High: VIP 체크인 예정 객실, 체크아웃 후 당일 재판매 객실 | |
|        | - Medium: 투숙 중 객실 불편, 미입실 객실 | |
|        | - Low: 일반 예방 정비 또는 미입실 빈 객실 | |
| WO-F12 | AI는 동일 유형의 반복 신고 패턴을 감지하여 근본 원인 점검을 제안해야 한다 | P2 |

### 1-3. 담당자 자동 배정

| ID | 요구사항 | 우선순위 |
|----|---------|---------|
| WO-F20 | 고장 유형과 긴급도에 따라 가용한 담당자에게 자동 배정 알림이 발송되어야 한다 | P0 |
| WO-F21 | 담당자가 배정 수락/거절을 할 수 있어야 하며, 거절 시 다음 순위 담당자에게 자동 재배정되어야 한다 | P1 |
| WO-F22 | 배정 후 일정 시간(Critical: 5분, High: 15분, Medium: 1시간) 내 수락이 없으면 상위 관리자에게 에스컬레이션 알림을 발송해야 한다 | P1 |
| WO-F23 | 외부 업체 호출이 필요한 경우 Work Order에 외부처리 플래그를 설정하고 업체 연락처를 기록할 수 있어야 한다 | P1 |

### 1-4. 진행 상황 추적 및 완료 처리

| ID | 요구사항 | 우선순위 |
|----|---------|---------|
| WO-F30 | 담당자는 모바일로 Work Order 상태를 실시간으로 업데이트(접수/진행중/완료/보류)할 수 있어야 한다 | P0 |
| WO-F31 | 완료 시 처리 내용, 소요 시간, 사용 부품/재료를 기록해야 한다 | P1 |
| WO-F32 | 완료 처리 시 신고자 및 관련 부서(프런트)에 자동 완료 알림이 발송되어야 한다 | P1 |
| WO-F33 | 하우스키핑 완료 시 PMS 연동을 통해 객실 상태(Clean/Ready)가 자동 업데이트되어야 한다 | P2 |

### 1-5. 처리 이력 및 보고서

| ID | 요구사항 | 우선순위 |
|----|---------|---------|
| WO-F40 | 모든 Work Order의 전체 이력(신고-배정-처리-완료)이 자동으로 기록되어야 한다 | P0 |
| WO-F41 | 관리자는 기간별, 부서별, 유형별 Work Order 처리 현황을 조회할 수 있어야 한다 | P1 |
| WO-F42 | 평균 처리 시간, 에스컬레이션 비율, 반복 고장 상위 항목 등 KPI 리포트를 제공해야 한다 | P1 |

## 2. 비기능 요구사항

| ID | 요구사항 | 기준 |
|----|---------|------|
| WO-NF01 | 신고 접수 → 담당자 알림 지연 | Critical 기준 30초 이내 |
| WO-NF02 | 모바일 최적화 | 담당자 앱은 3G 환경에서도 정상 동작해야 함 |
| WO-NF03 | 오프라인 지원 | 일시적 네트워크 단절 시 로컬 임시 저장 후 재연결 시 동기화 |
| WO-NF04 | 데이터 보존 | 완료된 Work Order 이력은 최소 3년 보존 |

## 4. 긴급도별 처리 SLA

| 긴급도 | 기준 | 배정 목표 | 완료 목표 |
|--------|------|---------|---------|
| Critical | 안전 위험, 투숙 불가 | 5분 이내 | 2시간 이내 |
| High | VIP 체크인 예정, 당일 재판매 객실 | 15분 이내 | 4시간 이내 |
| Medium | 투숙 중 불편 사항 | 1시간 이내 | 당일 |
| Low | 예방 정비, 빈 객실 | 4시간 이내 | 3일 이내 |

## 5. 사용자 시나리오

```
As a 하우스키핑 직원,
I want to 객실 결함을 발견하면 모바일로 즉시 신고하고 싶다,
So that 구두 전달 없이 시설팀이 바로 인지하고 처리를 시작할 수 있다.

As a 시설 엔지니어,
I want to 긴급도 순으로 정렬된 오늘의 Work Order 목록을 모바일로 확인하고 싶다,
So that 어떤 일을 먼저 해야 하는지 판단에 시간을 낭비하지 않을 수 있다.

As a 운영 관리자,
I want to 주간 Work Order 처리 현황과 반복 고장 패턴을 리포트로 보고 싶다,
So that 예방 정비 계획을 데이터 기반으로 수립할 수 있다.
```
