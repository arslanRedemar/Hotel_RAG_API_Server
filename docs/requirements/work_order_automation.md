# Work Order Automation — 업무 지시서 자동화 요구사항

> **영역**: AX 솔루션 핵심 기회 영역 3
> **우선순위**: 높음 (P1)
> **작성일**: 2026-03-29
> **버전**: 2.0

---

## 1. 배경 및 맥락 (Context)

### 1-1. 현재 상황

호텔에서 객실 결함은 매일 발생한다. 전구가 나갔을 때, 에어컨이 이상할 때, 욕실 배수가 느릴 때, 가구가 흔들릴 때 — 이것을 어떻게 처리하느냐가 고객 경험과 직결된다. 그런데 200실 규모 호텔에서 이 처리 흐름이 현재 어떻게 이루어지고 있는지를 보면 근본적인 문제가 있다.

**현재 Work Order 처리 흐름 (전화·구두 기반)**

```
하우스키핑 직원 발견
      ↓
슈퍼바이저에게 구두 보고 또는 카카오톡 메시지
      ↓
슈퍼바이저가 시설팀장에게 전화
      ↓ (이 시점에서 이미 기록이 없음)
시설팀장이 엔지니어에게 구두로 전달
      ↓
엔지니어가 처리 (언제 시작했는지 기록 없음)
      ↓
완료 후 시설팀장에게 구두 보고
      ↓
프런트는 언제 완료됐는지 모름
```

이 흐름에서 발생하는 핵심 문제:
1. **기록이 없다** — 무엇이 신고됐고, 누가 처리했고, 얼마나 걸렸는지 알 수 없다
2. **우선순위가 없다** — VIP 체크인 예정 객실과 빈 객실의 수리 요청이 같은 대기열에 있다
3. **책임 소재가 불분명하다** — "전달했다"와 "못 받았다"의 분쟁이 발생한다
4. **에스컬레이션이 없다** — 처리가 지연돼도 알 수가 없다

### 1-2. 정량적 현황 (추정)

| 지표 | 현재 상태 | 목표 |
|------|---------|------|
| Critical 결함 발견 → 처리 시작까지 | 평균 45분 (전달 지연 포함) | 5분 이내 |
| 처리 이력 보존율 | 약 20% (카카오톡 기록만) | 100% |
| 처리 완료 후 프런트 통보 누락율 | 약 40% | 0% |
| 동일 결함 반복 발생 감지 | 불가능 | 자동 감지 |
| 주간 처리 현황 보고 | 수작업 2~3시간 | 자동 생성 |

### 1-3. 이해관계자별 고통 포인트

**하우스키핑 직원**
- 결함을 발견해도 적절한 신고 채널이 없어 슈퍼바이저에게 카카오톡으로 보냄
- 신고 후 처리 여부를 확인할 방법이 없어, 같은 결함을 다시 신고하는 경우 발생
- 카메라로 사진을 찍어도 공유할 표준 방법이 없음

**시설 엔지니어**
- 하루에 처리해야 할 작업 목록이 없어 슈퍼바이저 전화를 기다려야 함
- "저거 고쳤어요?" 확인 전화가 하루에 10통 이상
- 어떤 작업을 먼저 해야 하는지 판단 기준이 없음 (모두 "빨리 해달라"고만 함)
- 처리 내역, 사용 부품을 기록하는 공식 채널이 없어 비용 산정 불가

**운영 매니저**
- 시설 관련 비용이 얼마나 드는지 파악 불가 (부품 사용 기록 없음)
- 같은 객실에서 같은 고장이 반복되는지 알 수 없어 예방 정비 계획 수립 불가
- VIP 불만 사례가 Work Order 지연과 연관됐다는 것을 사후에야 알게 됨

**프런트 오피스**
- 객실 수리가 완료됐는지 직접 시설팀에 전화해야 함
- 고객이 객실 상태를 문의해도 즉답 불가
- 체크아웃 후 객실 준비(C/I-Ready) 상태를 실시간으로 알 수 없음

### 1-4. 비즈니스 임팩트

**수익 손실**
- 처리 지연으로 인한 객실 판매 차단 시간: 추정 연간 수십 객실·박 손실
- VIP 고객 컴플레인 처리 비용: 룸 업그레이드, F&B 제공, 환불 등

**안전 리스크**
- Critical 결함(누전, 배관 파열, 비상구 막힘) 대응 지연 시 인명·재산 피해 가능
- 현재 안전 관련 결함의 즉시 에스컬레이션 체계 없음

**운영 효율**
- 시설팀 엔지니어의 이동 경로 최적화 불가 (작업 목록이 없으므로)
- 예방 정비 부재로 인한 갑작스런 대형 수리 비용 증가

## 2. 문제 정의 (Problem Statement)

> **"어떻게 하면 전화·구두 기반의 Work Order 처리 과정을 디지털화하여, Critical 결함은 발견 즉시 5분 이내에 적임자에게 배정되고 전체 처리 이력이 자동으로 기록되도록 만들 수 있을까?"**

---

## 3. 성공 비전 (Vision of Success)

도입 후 3개월 시점의 기대 모습:

- 시설 엔지니어가 출근하면 우선순위순으로 정렬된 오늘의 Work Order 목록이 모바일에 표시됨
- Critical 결함 발견 → 적임자 알림까지 30초 이내
- 모든 처리 이력이 자동 기록되어 주간 보고서가 버튼 한 번으로 생성
- 동일 객실에서 같은 유형의 고장이 3회 이상 반복될 경우 관리자에게 자동 알림

## 8. 사용자 시나리오

### 시나리오 A — 결함 발견에서 처리까지
```
상황: 하우스키핑 직원이 503호 욕실 조명이 고장난 것을 발견
      오늘 오후 VIP 체크인 예정 객실

As a 하우스키핑 직원,
I want to 모바일로 즉시 결함을 신고하고 VIP 체크인 전에 처리될 거라는 확인을 받고 싶다,
So that 담당자를 직접 찾아다니지 않아도 처리가 시작되는 것을 알 수 있다.

흐름:
1. 직원이 모바일로 신고 (객실 503, 전기, "욕실 조명 점등 불가" + 사진)
2. AI가 자동 분류: 카테고리=전기, 긴급도=High (VIP 체크인 예정)
3. 시설팀 엔지니어에게 즉시 알림 + SLA 마감(4시간) 표시
4. 직원에게 "접수 완료, WO-2026-03001, 예상 처리 시간: 4시간 이내" 알림
5. 엔지니어 배정 수락, 처리 완료 후 신고자·프런트에 완료 알림

수락 기준:
- 신고 → AI 분류 → 알림 발송까지 30초 이내
- High 배정 후 15분 이내 수락 없으면 자동 에스컬레이션
```

### 시나리오 B — 엔지니어의 모바일 업무 관리
```
As a 시설 엔지니어,
I want to 아침 출근 시 오늘 처리해야 할 Work Order를 긴급도 순으로 정렬된
          목록으로 모바일에서 확인하고 싶다,
So that 슈퍼바이저 전화 없이 내 판단으로 작업 순서를 정하고 바로 시작할 수 있다.

수락 기준:
- GET /work-orders?assigned_to=me&status=open&sort=severity 가 목록 반환
- 각 Work Order에 긴급도, SLA 마감 시각, 객실 번호, 사진 썸네일 포함
- 완료 처리 시 소요시간·부품 입력 화면으로 자동 전환
```

### 시나리오 C — 반복 고장 패턴 분석
```
As a 운영 매니저,
I want to 같은 객실에서 같은 유형의 고장이 반복될 때 즉시 알림을 받고 싶다,
So that "사후 수리" 방식에서 "예방 정비" 방식으로 전환하여 고장을 줄일 수 있다.

수락 기준:
- 503호 전기 고장이 90일 내 3회 발생 시 관리자에게 "반복 고장 감지" 알림
- 알림에 해당 Work Order ID 목록과 패턴 요약 포함
```
